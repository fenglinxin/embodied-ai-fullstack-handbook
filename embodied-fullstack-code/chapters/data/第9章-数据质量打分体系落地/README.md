# 第9章《数据质量打分体系落地》代码落地包

> 配套公众号文章：【具身智能全栈工程·第9章】"这批数据行不行"不能靠感觉
> 落地目标：可配置五维规则引擎 + 人工评审校准 + 双人盲审一致性。

## 1. 三层文件

| 文件 | 层 | 能力 |
| --- | --- | --- |
| `demo_quality_score.py` | L1 | 4 条样例五维打分（完整/正确/有效/可复现 + 数据集多样性），演示规则压分 |
| `engineering_quality_engine.py` | L2 | 规则注册表（可扩展）、权重可配、边缘区/低分区识别、自动-人工校准 gap、门禁 JSON |
| `advanced_quality_ops.py` | L3 | 双人盲审一致性率（分差≤0.1）、自动-人工系统性偏差告警、版本趋势对比 |

## 2. 环境

Python 3.9+，零第三方依赖（实测 3.13.3）。

## 3. 快速运行

```bash
cd 第9章-数据质量打分体系落地
python demo_quality_score.py --out records.json
# 构造两位评审（JSON 数组：episode_id + score_manual）
python engineering_quality_engine.py --input records.json \
    --review reviewers_a.json --out-dir out
python advanced_quality_ops.py --report out/quality_engine_report.json \
    --reviewer-a reviewers_a.json --reviewer-b reviewers_b.json --out-dir out
```

## 5. 参数白皮书

| 参数 | 默认/工程值 | 适配 | 禁忌 |
| --- | --- | --- | --- |
| weights | 25/30/15/20/10 | 第1章默认 | 力控任务提高正确性权重 |
| gate_score | 0.75 | 通用门禁 | 量产任务上调 0.85+ |
| edge 区间 | 0.55~0.85 | 人工全审触发 | 区间过宽=人工爆炸 |
| AGREE_TOL | 0.10 | 双人一致性 | 收紧前先修细则 |
| 偏差告警阈值 | 0.15 | 自动-人工校准 | 需区分随机噪声与系统性偏差 |

## 6. Top5 踩坑与修复

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 1. 平均分高但坏数据漏网 | 只看平均 | 看低分区+边缘区清单 |
| 2. 自动分和人工分系统性偏差 | 规则阈值与真实语义不符 | L3 校准告警 → 用人工分调规则 |
| 3. 双人打分差 30 分 | 细则不清 | L3 一致率<0.9 提示修订细则 |
| 4. 边缘区没人审 | 未标注 | L2 自动 zone=edge |
| 5. 打分器升级历史不可比 | 无版本 | 报告带 pipeline 版本/checksum |

## 7. 改造指南

- 自定义规则：在 L2 `rules()` 注册表追加函数，返回(分,原因)，自动进 JSON；
- 真实抽检：评审文件由标注平台导出即可；
- 版本对比：L3 `--previous` 接上一版 report 可看 avg/边缘区趋势（温水煮青蛙预警）。
