# 具身智能全栈工程专栏·全局代码落地强制规范

> 本规范用于给全系列 52+1 章公众号正文补齐"可运行、可复现、可改造"的工程代码。
> 目录约定：`chapters/<层>/第X章-主题/` 内含 `README.md`（配套文档）+ `demo` / `engineering` / `advanced` 三个代码文件 + `requirements.txt`。

## 一、三层代码强制结构（缺一不可）

| 层 | 文件约定 | 读者 | 目标 |
| --- | --- | --- | --- |
| L1 极简 Demo | `demo_*.py` | 零基础 | 依赖最少、零配置可跑，讲清本章核心机制 |
| L2 工业工程版 | `engineering_*.py` | 开发/项目工程师 | 参数校验、异常捕获、日志、配置解耦、批量与多场景兼容 |
| L3 高阶优化版 | `advanced_*.py` | 量产/进阶 | 提速/降显存/降噪/稳收敛/提精度/消除Sim2Real偏差/降抖动/提成功率 |

> 硬性要求：三个文件必须可独立运行；L1 优先标准库实现，保证"复制即跑"；L2/L3 依赖写入 `requirements.txt`。

## 二、代码配套强制字段（禁止裸代码）

每章 `README.md` 必须包含：

1. **环境依赖**：Python 版本、依赖库及版本、CUDA/仿真/硬件驱动适配、一键安装指令
2. **精细化注释**：核心逻辑、关键公式、分支判断、模块交互逐段注释
3. **核心参数白皮书**：默认值 / 最优工程值 / 适配场景 / 禁忌场景
4. **标准运行结果示例**：真实终端输出或数据返回格式
5. **Top5 高频踩坑修复**：报错/失效/真机异常 → 根因 → 一键修复
6. **二次开发改造指南**：自定义数据/硬件/场景/接入全工程链路

## 三、分层代码风格基线（全专栏统一）

- Python ≥3.9；`from __future__ import annotations`；类型注解齐全
- 函数单一职责；主入口 `if __name__ == "__main__":`
- 日志：`logging`，格式 `时间 [级别] 模块:消息`
- 配置：dataclass 或 `config.yaml` + CLI 覆盖，禁止魔法数字裸奔
- 路径：全部相对工程根目录或显式传入，禁止依赖 `os.getcwd()` 隐式假设
- 结果：输出 JSON 报告（可机读）+ 人类可读摘要；所有脚本退出码 0/1/2
- 代码内附"防幻觉"自查：只使用标准库或 requirements 中声明的 API

## 五、知识闭环转化流程（每章固定执行）

1. 提炼本章 TOP3 理论 → 核心工程痛点
2. 痛点 → 必须落地的代码能力清单
3. 输出 极简Demo → 工程标准版 → 高阶优化版
4. 配套踩坑修复 + 参数调优 + 异常处理
5. 给出下一阶段进阶改造方向
