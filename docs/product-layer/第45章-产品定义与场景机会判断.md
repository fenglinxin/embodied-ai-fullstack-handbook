> 副标题：产品化与产业层开篇——JTBD、场景打分、ROI 算账、TAM/SAM/SOM，从"能做"到"该做哪个"。
> 系列：具身智能全栈工程落地（产品产业层第 1 篇）｜独立成篇，可单篇收藏

## 📌 开篇钩子

全栈工程能力齐了（数据→模型→仿真→硬件→部署），创始团队开始面对终极拷问：**做什么产品、进哪个场景、卖给谁、怎么赚钱？**

具身智能最大的产业陷阱是"技术自嗨"：人形机器人什么都能干 → 等于什么都不精 → 客户不知道买来干什么 → 沦为展厅摆设。另一个陷阱是"伪需求"：demo 时客户说"太好了"，掏钱时却说"再等等"——因为**没算清它替客户省了多少钱、自己能不能赚钱**。

产品定义的本质是"选择"：选场景（痛点够痛）、选任务（技术够得着）、选客户（有钱且愿意付）、算账（ROI 双方都成立）。本章给一套从"一堆想法"到"一个产品定义"的方法：JTBD 需求拆解、场景打分矩阵、单位经济模型、以及"先窄后宽"的落地路径。

## 一、章节定位与适用人群

**章节定位**：产品化与产业层（从技术到商业的第一跳）。解决的核心问题：**技术强但不知道做什么产品、场景选择靠拍脑袋、商业模式算不清账**。

**适用场景**：创业者/产品经理 ☑（重点）企业战略/BD ☑ 工程师转型管理 ☑
**建议阅读时长**：14 分钟（建议收藏，立项与融资前对照）

**读完你将能**：
1. 用 JTBD 把"客户需求"拆成可验证的任务；
2. 用场景打分矩阵筛出"痛、近、赚"的切入点；
3. 用单位经济模型判断产品能不能成立。

## 二、大白话原理：产品定义回答四个问题

### 2.1 四个问题（缺一个都是空中楼阁）

1. **为谁**：哪个客户的哪个岗位（不是"企业"这种虚词）；
2. **解决什么**：他要完成的"任务"（JTBD：客户雇机器人干什么活）；
3. **凭什么选你**：比人工/比传统自动化/比竞品好在哪（可量化）；
4. **怎么赚钱**：客户 ROI 成立 + 你的毛利成立。

> 💡 金句：**客户不买"机器人"，客户买"这个活儿有人/有机器替我干了，还划算"。**

### 2.2 为什么"场景越窄越容易成"？

窄场景意味着：任务可定义、技术可收敛、验收可量化、数据可聚焦（第 7 章）——全栈工程的所有方法都依赖"任务边界清晰"。**先在一个窄场景做到 99%，再横向扩展，是具身智能产品化的主流路径**；一上来就"通用"，会同时输给所有专用方案。

## 三、分步实操：从想法到产品定义六步

### 第 1 步：列候选场景池（发散）
从产业环节（工业/商业/家庭/特种）列出 10–20 个候选任务，如：仓库拆码垛、产线上下料、门店补货、餐厅收盘、病房配送、家庭收纳……**先别评判，全部列出**。

### 第 2 步：JTBD 拆解（每个候选做一张卡）
对每个候选任务问：
- 谁在做这件事？一周做几次？每次多久？
- 现在怎么做的（人工/传统设备）？成本多少？
- 最大的痛是什么（招不到人/效率/安全/质量）？
- 如果机器人来做，省的是什么、风险是什么？
> 一张卡写不满三行"真实的人与数字"，说明需求还没想清楚。

### 第 3 步：场景打分矩阵（收敛）

| 维度 | 权重（例） | 打分 1–5 |
| --- | --- | --- |
| 痛点强度（客户多痛） | 25% | |
| 支付意愿（预算/合同现实） | 20% | |
| 技术可达（以你当前栈评估） | 20% | |
| 数据可得（第 7 章） | 15% | |
| 竞争密度 | 10% | |
| 政策/安全风险 | 10% | |

打分要"用证据打"（访谈/调研/试用），不是头脑风暴拍分；取前 2–3 名进入下一步。

### 第 4 步：单位经济模型（算账）
对候选场景算两个账：
- **客户账**：机器人月成本 vs 替代的人工/旧方案月成本 + 效率/质量收益 → 回本周期（<12–18 个月通常才好卖）；
- **你的账**：单台硬件 BOM+毛利、软件/服务收入、交付成本、运维成本 → 单台毛利与盈亏平衡量。

**常见死法**：客户账成立但你的账不成立（硬件太贵卖不动），或你的账成立但客户账不成立（省的钱不够付你）。

### 第 5 步：MVP 产品定义（窄而深）
选定一个切入点后，写产品定义：
- 场景/任务/客户画像（一页纸）；
- **任务边界**：做什么、明确不做什么（第 44 章需求书前身）；
- 成功指标：节拍/成功率/可用性/回本周期；
- 技术基线：复用哪些全栈资产（数据/模型/仿真/硬件），缺口是什么；
- 里程碑：3/6/12 个月验证什么。

### 第 6 步：验证闭环（别急着造 100 台）
1. 用手工/半自动方案先给客户跑通流程（验证需求真实性）；
2. 1–2 台样机在真实场景小范围试运行（验证技术与 ROI）；
3. 客户付费意向（意向金/合同）比口头夸奖可靠；
4. 验证不过就换场景（回到第 3 步），别在错场景里硬磨。

## 四、核心参数详解

| 参数 | 建议参考 | 作用 | 备注 |
| --- | --- | --- | --- |
| 客户回本周期 | ≤12–18 个月 | 需求真实性 | 分场景 |
| 单台毛利目标 | ≥30–40%（硬件） | 商业模型 | 加服务收入 |
| 场景打分证据 | 访谈 ≥10 家客户 | 收敛依据 | 量化痛点 |
| MVP 台数 | 1–2 台 | 验证 | 别先造百台 |
| 试用周期 | 1–3 个月 | 真实 ROI | 收意向金 |
| 任务成功率 | ≥99%（按场景） | 产品底线 | 全栈方法保障 |

## 五、高频踩坑清单

| 现象 | 根因 | 排查 | 解决 |
| --- | --- | --- | --- |
| 客户说好但不买 | 伪需求/ROI 不成立 | 算客户账 | 意向金+试用验证 |
| 什么场景都做 | 没做收敛 | 打分矩阵 | 聚焦前 2–3 名 |
| 技术 demo 强产品卖不动 | 没算你的账 | 单位经济 | 硬件成本/毛利重构 |
| 场景太宽技术够不着 | 任务边界不清 | JTBD 卡 | 窄场景切入 |
| 访谈客户全是客套 | 问法不对 | 问"现在花多少钱" | 量化问题+现场观察 |
| 一上来造 100 台 | 没验证 | 看订单 | 1–2 台试运行 |
| 只算硬件不算服务 | 账算不全 | 全生命周期 | 加交付/运维/升级 |
| 对标"未来市场"忽略了当下 | 无 TAM 分层 | TAM/SAM/SOM | 先吃 SOM（可服务市场） |

## 六、进阶优化

1. **"场景-能力"双轮规划**：场景选择反过来定义技术栈优先级（数据采什么、模型训什么、硬件配什么），技术与商业对齐，避免"先造锤子再找钉子"。
2. **灯塔客户共创**：选 1–2 家愿意共创的灯塔客户（给折扣换真实反馈与背书），比 10 家"感兴趣"值钱。
3. **从"卖硬件"到"卖结果"**：按"每箱/每小时/每次任务"计价（Robot-as-a-Service），降低客户决策门槛，前提是你的稳定性工程（第 43 章）真的过硬。
4. **产业复盘常态化**：产品定义不是一次性的——每季度用真实运营数据回看场景假设（第 52 章产业趋势联动），该 pivot 就 pivot。

---

## 七、本章 TOP3 核心总结

1. **产品定义 = 四个问题的答案**：为谁、解决什么任务、凭什么选你、怎么赚钱；窄场景先做到 99% 再扩展。
2. **场景打分要证据、算账要双向**：客户回本周期 ≤12–18 个月 + 你的单台毛利 ≥30–40%，两个账都成立才开工。
3. **先窄 MVP 验证再放量**：手工跑通→1–2 台试用→意向金验证，别用 100 台样机验证一个猜想。

> 📌 记住这一句：**客户买的从来不是机器人，是"划算地解决一个具体问题"——产品定义就是把这个划算讲清楚、做出来。**
