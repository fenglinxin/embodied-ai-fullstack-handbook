## 📌 开篇钩子

VLA 与基础模型的 Demo 都很震撼，但项目验收问的是：**这模型能跑在我们那块 30W 的板子上吗？延迟压到 50ms 了吗？换到量产型号还能保持 99% 成功率吗？**

答案通常藏在三个工程动作里：**微调**（把通用模型变成你的模型）、**蒸馏**（把大模型变成小模型）、**轻量化**（把小模型塞进端侧硬件）。这三步是模型从"论文资产"变成"产品零件"的最后一公里——也是翻车率最高的地方：微调把通用能力冲没了、蒸馏把动作细节丢了、量化把成功率从 98% 干到 60%。

本章把三者串成一条适配流水线，讲清各自适用时机、标准做法、评测方法与避坑点，为后续部署章节（第 38 章起）打底。

## 二、大白话原理：三个动作解决三类问题

| 动作 | 解决什么 | 通俗类比 |
| --- | --- | --- |
| 微调 | 通用能力 → 你的任务/本体 | 大学毕业生 → 岗位培训 |
| 蒸馏 | 大模型 → 小模型 | 老专家带徒弟，徒弟学会"判断"而不是背答案 |
| 轻量化 | 小模型 → 端侧实时 | 精装修搬家：能省的重量都省掉 |

三者常常接力：**开源大 VLA → 领域微调 → 蒸馏成小模型 → 量化上端侧**。每一步都可能掉精度，所以要给每一步配"验收闸门"。

> 💡 金句：**蒸馏与量化的目的不是"逼近原模型"，而是在任务指标上"守住红线"。**

## 三、技术选型：三条路线怎么选

### 3.1 微调路线

| 路线 | 机制 | 成本 | 适用 | 风险 |
| --- | --- | --- | --- | --- |
| 全参数微调 | 所有权重更新 | 高（显存/数据） | 任务差距大、数据足 | 灾难性遗忘 |
| LoRA 类 PEFT | 冻结主干只训低秩增量 | 低 | 领域微调默认首选 | 容量有限 |
| QLoRA | 量化基座+LoRA | 最低 | 单卡起步 | 训练慢一点 |
| 多任务持续微调 | 新任务接续训练 | 中 | 技能持续积累 | 旧任务回退 |

### 3.2 蒸馏与轻量化路线

| 手段 | 原理 | 收益 | 注意 |
| --- | --- | --- | --- |
| 输出蒸馏 | 学生学老师的动作/概率分布 | 模型变小 | 动作分布细节别丢 |
| 任务蒸馏 | 学生直接学老师"做对任务"（含失败回退） | 更贴近目标 | 需要任务数据 |
| PTQ（训练后量化） | 直接转 INT8/INT4 | 快 | 精度可能掉 |
| QAT（量化感知训练） | 模拟量化误差重训 | 精度稳 | 训练成本高 |
| 剪枝/结构化稀疏 | 删冗余参数/头 | 变小变快 | 硬件加速支持有限 |

**选型结论（工程默认路径）**：微调先 LoRA（数据不足/迭代快），蒸馏先输出蒸馏后任务蒸馏，量化先 PTQ 试水、掉点超红线再 QAT——**每步都从最便宜的方案开始，用数据说话再升级**。

## 四、分步实操：模型适配流水线

### 第 1 步：定"任务红线"（所有步骤的共同基准）

上线前先定义：
- 核心指标：任务成功率/动作误差/延迟 P95/显存上限；
- **红线**：量化/蒸馏后核心指标允许掉的幅度（如成功率 ≤2 个点、延迟达标）；
- 评测集：固定黄金评测集（第 12 章），真机+仿真两套。

### 第 2 步：微调（默认 LoRA 起步）

1. 数据组织：指令-观测-动作-结果（第 22 章流程）；
2. LoRA rank 从 16–64 试；学习率按官方基线 1e-4~1e-5 量级起；
3. **混合通用数据**（如 10%–30%）防灾难性遗忘；
4. 验收：领域任务涨 + 通用任务不掉（两套评测都要跑）。

### 第 3 步：蒸馏（需要端侧小模型时）

1. 选学生架构：小 VLM/轻量动作头（按端侧算力预算定规模）；
2. 数据：老师能"做对"的多样化任务数据（老师犯错的数据少用）；
3. 训练：模仿老师动作 +（可选）对齐老师特征/分布；
4. **验收重点是动作级与任务级**：单步动作误差可容忍，但任务成功率必须守红线；
5. 若蒸馏后卡在瓶颈：回到数据与架构（学生太小就换大一号），别硬压。

### 第 4 步：轻量化（量化/剪枝/导出）

1. 先做**端到端剖析**（第 21 章延迟预算思想）：瓶颈在骨干、动作头还是预处理？
2. PTQ 试点：INT8 通常稳；INT4 需要校准集与更小心；
3. 掉点分析：看哪类样本掉（长尾/小目标/罕见动作）→ 针对性 QAT/混合精度（敏感层保持高精度）；
4. 导出与验证：ONNX/TensorRT 等（部署章节详述），**导出后必须重跑黄金评测**——框架转换本身也会引入误差。

### 第 5 步：端侧整机验收

- 与第 22 章真机接入一致：安全壳 + 失败回退；
- 跑"长时间稳定性"：显存泄漏、温度降频、偶发慢帧；
- 记录端到端延迟 P95 与任务成功率，与红线对照。

## 五、核心参数详解

| 参数 | 建议起点 | 作用 | 备注 |
| --- | --- | --- | --- |
| LoRA rank | 16–64 | 微调容量 | 差距大再上调 |
| 通用数据混合比 | 10%–30% | 防遗忘 | 按回退评测调 |
| 蒸馏学生规模 | 按端侧预算 | 速度/精度 | 别小于任务所需 |
| 量化位宽 | INT8 起步 | 压缩 | INT4 需仔细校准 |
| 成功率红线 | 掉点 ≤1–3 个点 | 质量门禁 | 按业务定 |
| 校准集 | 500–2000 条代表样本 | PTQ/QAT | 覆盖难例 |
| 延迟 P95 目标 | 任务预算（如 50–200ms） | 上线 | 与动作块配合 |

## 六、高频踩坑清单

| 现象 | 根因 | 排查 | 解决 |
| --- | --- | --- | --- |
| 微调后通用能力崩 | 数据全领域化/学习率大 | 通用评测 | 混合数据+低学习率 |
| 蒸馏后"动作像了任务失败" | 只对齐输出没对齐任务目标 | 任务级评测 | 加任务蒸馏/失败回退数据 |
| 量化后小目标全丢 | 校准集缺难例/INT4 太激进 | 分样本类掉点分析 | 难例校准+混合精度 |
| 导出后行为变了 | 框架算子差异 | 逐层对比 | 算子替换/保精度模式 |
| 延迟没降多少 | 瓶颈在预处理/动作头 | 端到端剖析 | 优化全链路而非只量化骨干 |
| 显存降了速度没升 | 带宽受限 | 看硬件指标 | 量化+算子融合一起做 |
| 蒸馏学生一直追不上 | 学生太小/老师数据不够好 | 换大一号学生 | 架构与数据双修 |
| 每一步都掉一点，最后崩盘 | 无中间门禁 | 各步红线评测 | 每步单独验收再进下一步 |

## 七、进阶优化

1. **"先蒸馏任务、再量化"的顺序**：任务蒸馏放在量化前，让量化前的模型已经"小而准"，量化只承担最后一小段压缩。
2. **混合精度部署**：视觉编码器 INT8、动作头 FP16、敏感层保持高精度——用最少的位宽损失换最大压缩。
3. **持续学习与模型动物园**：按技能/任务维护多个 LoRA 增量 + 路由选择，比反复全量微调更稳（对应技能库思想）。
4. **上线后监控蒸馏/量化漂移**：端侧版本与教师版本定期在黄金集上对比，漂移超限触发重新适配——模型也要"保养"。

## 八、本章 TOP3 核心总结

1. **适配接力三件套**：LoRA 微调（领域化）→ 任务蒸馏（变小）→ 量化/导出（上端侧），每步都设精度红线与黄金评测。
2. **红线先行**：成功率/延迟/显存上限在动手前定死，所有取舍用评测说话，不凭感觉。
3. **端到端剖析定瓶颈**：延迟与显存优化先找瓶颈（骨干/动作头/预处理），别默认"量化骨干就完事"。

> 📌 记住这一句：**模型适配的目标不是"和老师一样强"，而是"在端侧硬件上守住任务红线"。**
