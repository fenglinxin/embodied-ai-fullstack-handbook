## 📌 开篇钩子

很多具身团队的第一笔大额支出，是在"看起来不错"的硬件上：买了双足人形发现只做桌面抓取（白白扛着 20kg 腿在跑）、买了两台工业臂做演示（成本是协作臂的 5 倍）、攒了台双 GPU 工控机（结果车载供电带不动、一颠就重启）。

**硬件选型的本质是"需求翻译"**：任务需要什么运动能力 → 需要什么本体 → 需要多少算力与接口 → 需要什么供电与可靠性。翻译错了，后面每一层（驱动、标定、算法、量产）都在给选型错误还债。

本章给硬件选型提供完整框架：本体形态怎么定、算力平台怎么配、整机架构（感知-计算-执行-供电）怎么设计，以及量产视角下必须提前问的问题。

## 二、大白话原理：硬件选型是"需求翻译"

### 2.1 先问任务，再问形态

| 任务特征 | 导向的本体形态 |
| --- | --- |
| 固定工位、桌面操作 | 固定机械臂/协作臂 |
| 大范围移动+拿取 | 移动底盘+机械臂（复合机器人） |
| 上楼、过窄空间 | 双足/轮足人形 |
| 双手精细操作 | 双臂（固定/移动） |
| 人形交互/通用家务 | 人形/仿人上半身 |

**关键判断**：任务需要的其实是"手臂+移动"的组合，而不是"人形"这个形态。**形态越复杂，成本、故障率与调试成本越高**——能用车轮别用腿，是硬件选型第一定律。

### 2.2 五个反推问题

1. 末端载荷与速度：决定臂的负载与减速比；
2. 工作空间：决定臂长与底座自由度；
3. 精度需求：决定减速器等级（谐波/RV/行星）与编码器；
4. 交互安全：决定是否协作臂/力控/防护；
5. 运行时长与供电：决定电池/电源与整机功耗预算。

> 💡 金句：**好的硬件选型让算法"够得着"，差的硬件选型让算法"够不着还要背一堆重量"。**

---

## 三、选型对比：三大本体方向

| 维度 | 固定/协作机械臂 | 移动底座+臂（复合） | 人形/双足 |
| --- | --- | --- | --- |
| 典型任务 | 产线抓取、装配 | 巡检、物料搬运、商服 | 通用操作、人形交互 |
| 优点 | 精度高、便宜、成熟 | 覆盖大空间 | 形态通用、未来空间大 |
| 难点 | 场景固定 | 底盘-臂协同、供电 | 平衡、可靠性、成本 |
| 成本量级 | 低-中 | 中-高 | 高-很高 |
| 量产成熟度 | 高 | 中 | 低-中 |

**结论（默认路径）**：先用**最简形态**（固定臂或轮式+臂）把任务跑通；人形只在"任务确实需要仿人形态"（上下楼、进家门、人形交互）时选择——别为"酷"付十倍成本。

## 四、分步实操：整机架构设计五步

### 第 1 步：运动执行子系统
- 关节：电机+减速器+编码器+驱动器（力矩/电流环，第 19–21 章控制需要）；
- 通信：EtherCAT/CAN 等实时总线（第 36 章细讲）；
- 关键参数表：自由度、负载、速度、重复精度、力矩上限、关节限位。

### 第 2 步：感知子系统（按第 13–15 章需求配）
- 视觉：RGB/深度/鱼眼，位置（手眼/外置）与数量按任务定；
- 本体：IMU、关节编码器（自带）、力/力矩（按接触任务）；
- 其他：激光（移动导航）、触觉（灵巧手，按需）；
- 接口预算：相机数量 × 带宽/帧率是否吃得下。

### 第 3 步：计算子系统（算力怎么定？）
1. 列"实时负载清单"：感知模型×频率、规划、控制、VLA（第 22–24 章）；
2. 分别估算：延迟预算内需要的算力（TOPS/FLOPS）与显存；
3. 分层放算力：**实时控制**（低延迟）用小核/独立控制器，**AI 推理**（重负载）用 GPU/NPU 类加速器，**系统管理**用轻量 CPU；
4. 选型关注：总算力、可用显存、功耗、散热、接口（相机数量）、车规/工规可靠性；
5. 记住第 24 章的教训：**先定模型与延迟预算，再定算力**，别先买卡再塞模型。
> 具体芯片/模组（如 NVIDIA Jetson 系列等）迭代快，以官方规格与你的实测为准。

### 第 4 步：供电与热设计（最容易被低估）
- 估算峰值功耗：关节急加速 + AI 推理峰值同时出现；
- 电池：容量（运行时长）、放电倍率（峰值电流）、保护；
- 电源树：数字/模拟/电机功率分开、防浪涌、掉电顺序；
- 热：计算与驱动器的散热余量（长时间满载不降频）；
- 实测规则：**按"最坏工况持续 1 小时"验收，不是按平均功耗**。

### 第 5 步：整机集成与接口图
画一张整机架构图：感知 →（时间同步）→ 计算 → 实时控制 → 执行；供电树与通信拓扑并列；每个接口标注协议/带宽/延迟预算。**这张图是后续驱动、联调（第 35–37 章）与排障的地图**，务必维护版本。

## 五、核心参数详解

| 参数 | 怎么定 | 备注 |
| --- | --- | --- |
| 自由度 | 任务所需（宁缺毋滥） | 每个自由度都是成本 |
| 负载 | 末端工具+工件+余量 | 别卡死极限 |
| 重复精度 | 任务公差反推 | 装配严、搬运松 |
| 算力（AI） | 模型×延迟预算实测 | 先定模型再选卡 |
| 整机峰值功耗 | 最坏工况实测 | 供电按峰值 |
| 运行时长 | 业务节拍+安全余量 | 电池按峰值放电 |
| 通信总线 | 实时性与带宽 | 控制实时总线独立 |

## 六、高频踩坑清单

| 现象 | 根因 | 排查 | 解决 |
| --- | --- | --- | --- |
| 买完发现自由度不够 | 任务拆解晚了 | 任务树复盘 | 先拆任务再定自由度 |
| 算力买小了模型跑不动 | 先买卡后定模型 | 延迟实测 | 模型-算力联合预算 |
| 一急停/颠簸就重启 | 供电余量不足 | 看掉电日志 | 峰值供电+UPS/电容 |
| 电池 2 小时标称 20 分钟实际 | 按平均功耗选电池 | 峰值电流实测 | 按峰值倍率选 |
| 相机太多接口不够 | 没做带宽预算 | 接口清单 | 分层/分时/换接口 |
| 形态选复杂了成本爆炸 | 没做需求翻译 | 形态决策表 | 最简形态起步 |
| 工控机一满载就降频 | 散热设计不足 | 温度监控 | 散热余量+降频策略 |
| 算法与硬件接口对不上 | 无整机架构图 | 接口清单 | 架构图版本化 |

## 七、进阶优化

1. **"硬件-算法"联合预算表**：把延迟、带宽、功耗、算力放在一张表里做预算（感知 ms + 规划 ms + 控制 ms ≤ 任务预算），所有选型决策对照此表。
2. **平台化选型**：同一平台覆盖多个产品 SKU（不同臂长/相机配置可换），降低备件与维护成本。
3. **数字孪生先行**：硬件改动先在仿真验证（第 25–26 章），再动真机——人形等昂贵平台尤其重要。
4. **量产视角前置**：样机阶段就问：BOM 成本、供货周期、备件、认证（CE/UL 等按市场）、产线装配性——**样机跑通但无法量产的硬件，等于白选**。

---

## 八、本章 TOP3 核心总结

1. **需求翻译优先**：任务→运动→本体→算力→整机五步反推；形态越复杂成本越高，"能用车轮别用腿"。
2. **算力与供电按"最坏工况"定**：模型延迟预算先行，峰值功耗/散热实测验收，不按平均。
3. **整机架构图是地图**：感知/计算/控制/供电四大子系统 + 接口/带宽/延迟预算版本化，后续所有联调排障都靠它。

> 📌 记住这一句：**硬件选型省下的每一分钱，都会在联调与量产时加倍还回去——除非你一开始就选对了。**
