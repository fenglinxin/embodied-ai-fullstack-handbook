## 📌 开篇钩子

机器人系统的软件栈有个经典矛盾：**AI 想要 Linux 的生态与算力，控制想要"死也要按时"的确定性**。让一个跑着 PyTorch、动不动 GC/换页的上位机直接发关节指令，是事故的起点；让实时控制器去跑 VLA 推理，又是算力的灾难。

于是几乎所有工业机器人都有一个心照不宣的分层：**上位机（大脑）负责智能，下位机（小脑/脊髓）负责实时执行**。中间隔着的不是"一个函数调用"，而是一整套精心设计的通信、时钟与失效保护。

本章讲上下位机架构：分工与接口怎么定、ROS 2/DDS 通信怎么配实时性、实时内核与延迟预算怎么做、以及"上位机死了机器人该怎么办"的失效安全设计——硬件层收官，系统软件正式接管。

## 二、大白话原理：为什么必须分层？

### 2.1 两类任务的"性格"完全不同

| | 上位机（智能层） | 下位机（实时层） |
| --- | --- | --- |
| 跑什么 | 感知/规划/VLA、状态机 | 轨迹插补、闭环控制、安全 |
| 需要 | 生态、算力、灵活性 | 确定性、低抖动、可靠性 |
| 典型系统 | Linux + AI 框架 | 实时内核/RTOS/专用控制器 |
| 频率 | 1–30Hz 波动可容忍 | 100Hz–1kHz+，抖动要极小 |
| 故障影响 | 任务中断 | **直接威胁安全** |

混跑的结果是"互相伤害"：AI 的偶发卡顿变成控制抖动，控制的实时线程抢走 AI 的算力。**分层后各司其职，中间用有界延迟的通信连接**。

### 2.2 分层不是"两台电脑"那么简单

分层可以是物理两台（工控机+控制器）、虚拟机/容器隔离、或同一 SoC 的大小核/独立 RT 核——关键不是"几台机器"，而是**实时任务与非实时任务之间的隔离边界**。

> 💡 金句：**上位机负责"想得对"，下位机负责"动得稳、停得下"——边界清晰，系统才敢跑得快。**

## 三、分步实操：上下位机架构五步

### 第 1 步：划分功能边界与接口契约

| 层 | 职责示例 | 不做什么 |
| --- | --- | --- |
| 上位机 | 感知融合、任务/路径规划、VLA 推理、人机交互 | 不直接发关节电流 |
| 下位机 | 轨迹插补、位置/速度/力矩环、急停与限位 | 不做重型 AI |
| 接口 | 目标位姿/轨迹/速度指令 + 状态回读 + 使能/模式 | 禁止绕道直连 |

**接口契约**：指令数据结构（位姿/速度/模式/时间戳）、状态回读（实际位姿/电流/错误码）、**每个指令必须带"过期时间"**——超过有效期的指令直接丢弃，防止"迟到的大脑指令"被执行。

### 第 2 步：选通信方案并配实时性

| 方案 | 特点 | 适用 |
| --- | --- | --- |
| EtherCAT/CANopen（控制总线） | 微秒级确定性 | 下位机-驱动器（第 33/34 章） |
| ROS 2 / DDS（智能层） | 灵活、生态好 | 上位机内部与上下位机之间 |
| 共享内存/专用通道 | 最低延迟 | 同机高性能路径 |

**ROS 2/DDS 实时性四件套**：
1. QoS 选型：控制指令用 best_effort + 小 depth（宁丢旧帧不发迟帧），状态回读用 reliable 按需；
2. 实时内核（PREEMPT_RT）：DDS 与关键节点跑 RT 线程；
3. 锁内存/禁换页、CPU 亲和性：控制与 DDS 线程钉核；
4. 网络/共享内存传输按拓扑选型，测 P99/P99.9 抖动。

### 第 3 步：做延迟预算表（架构的验收标准）

从"传感器事件"到"执行器响应"画完整链路，每段标预算（第 21 章方法）：感知 20ms + 规划 30ms + 通信 5ms + 控制 1ms…；**重点盯 P99 与抖动**，不是平均值。预算超了先找瓶颈段（profiling），再决定优化（降频、异步、并行）还是重分边界。

### 第 4 步：失效安全设计（上位机死了怎么办）

| 失效模式 | 兜底策略 |
| --- | --- |
| 上位机卡死/断连 | 下位机指令超时 → 减速停车/保持安全位姿 |
| 通信丢包风暴 | 看门狗 + 指令过期丢弃 + 降级模式 |
| 下位机故障 | 安全停车链（独立急停回路，不经上位机） |
| 传感器失效 | 降级到保守模式（第 15 章模态降级） |

**铁律**：急停与安全回路必须**独立于上位机**（纯硬件/下位机实现）；上位机任何软件 bug 都不能绕过安全链。

### 第 5 步：验收实验

- 抖动测试：上位机满载（AI 推理+磁盘 IO）时，控制周期抖动仍在预算内；
- 断连测试：拔掉上位机通信，机器人应安全停车而非乱动；
- 注入测试：人为延迟/丢包，观察系统行为符合设计；
- 长跑：连续运行数小时无累积漂移（第 21 章方法）。

## 四、核心参数详解

| 参数 | 建议起点 | 作用 | 备注 |
| --- | --- | --- | --- |
| 控制周期 | 1–10ms（按平台） | 稳定性 | 抖动 ≤ 周期 10–20% |
| 指令有效期 | 2–5 个控制周期 | 防迟到指令 | 超期丢弃 |
| QoS depth | 1–5（控制指令） | 时效性 | best_effort |
| RT 线程 | 控制/DDS 钉核 | 抖动 | 锁内存 |
| 安全停车时间 | 按动能与场景 | 安全 | 独立回路 |
| 通信 P99 | 预算内 | 架构验收 | 满载测 |

## 五、高频踩坑清单

| 现象 | 根因 | 排查 | 解决 |
| --- | --- | --- | --- |
| AI 一推理机器人就抖 | 上下位机没隔离 | 满载抖动测试 | 分层/钉核/RT 内核 |
| 指令迟到被当成新指令执行 | 无过期机制 | 看指令时间戳 | 有效期+丢弃 |
| 上位机重启机器人乱动 | 无失效安全 | 断连测试 | 超时安全停车 |
| DDS 丢包导致控制断断续续 | QoS 配置错 | 看丢包统计 | reliable/深度/QoS 匹配 |
| 通信平均快但偶尔爆 | 未优化尾部延迟 | P99 分析 | RT/锁内存/网络隔离 |
| 两台"机器"时间不对 | 无统一时钟 | 时间偏差测量 | PTP（第 35 章） |
| 急停要等上位机响应 | 安全链依赖软件 | 急停测试 | 独立硬件安全链 |
| 边界不清各写各的 | 无接口契约 | 看代码耦合 | 契约+代码评审 |

## 六、进阶优化

1. **影子模式与热切换**：新算法在上位机"影子运行"（只算不下发），对比决策差异稳定后再切换——系统升级零风险。
2. **状态机下沉**：关键任务状态机（第 18 章）放下位机/近实时层，上位机只给"意图"，故障时下位机能独立完成安全收尾。
3. **可观测性内置**：每条指令/状态带时间戳与链路 ID，跨层延迟一图看全（呼应第 11 章血缘思想）。
4. **确定性仿真先行**：架构改动先在 HIL（硬件在环）里注入延迟/故障验证，再上真机——第 25–31 章仿真能力在此复用。

## 七、本章 TOP3 核心总结（硬件层收官）

1. **智能与实时必须分层**：上位机想得对、下位机动得稳，中间是有界延迟通信+过期丢弃的指令契约。
2. **实时性 = QoS + RT 内核 + 钉核 + 延迟预算**：验收看满载下的 P99 抖动，不是空载平均。
3. **失效安全独立于上位机**：急停/安全回路纯硬件/下位机实现，断连必安全停车——这是量产的底线。

> 📌 记住这一句：**上位机决定机器人聪不聪明，下位机决定它出事后安不安全——两者都合格，系统才成立。**
