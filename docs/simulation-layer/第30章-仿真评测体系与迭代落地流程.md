## 📌 开篇钩子

"仿真成功率 95%，可以上真机了！"——这句 Flag 的含金量，完全取决于评测协议怎么写的。同样是 95%：可能是"固定种子 10 次、物体摆位从不随机"的 95%，也可能是"1000 次随机变体、多随机种子、含失败恢复"的 95%。**前者是自嗨，后者才算数。**

更麻烦的是：仿真评测和真机表现常常"不成正比"。仿真 95% 可能对应真机 30%，仿真 70% 可能对应真机 70%——**评测体系的真正目标不是分数高，而是"仿真分数能预测真机表现"**。

本章讲仿真评测体系：评测协议五要素、指标分层、回归基准怎么搭、以及"仿真-真机对齐"的迭代落地流程，让你每次"可以上真机了"都有据可依。

## 二、大白话原理：评测是"用统计对抗运气"

### 2.1 为什么仿真评测会骗人？

| 骗人来源 | 例子 |
| --- | --- |
| 变体太少 | 只测固定摆位 |
| 种子太少 | 同一随机下碰运气 |
| 协议不一致 | 训练与评测用同一批场景 |
| 只看成功率 | 不看失败模式、节拍、安全 |
| 仿真漏洞 | 策略 exploit 了 reset/奖励 bug |

**评测协议的本质**：规定"考什么题、考多少遍、怎么判卷"，让分数具备统计意义与可比性。

### 2.2 评测的三层指标

1. **任务层**：成功率、完成节拍（平均耗时）、失败模式分布——决定"行不行"；
2. **行为层**：轨迹平滑度、接近安全距离频率、急停次数——决定"像不像样"；
3. **资源层**：推理延迟、显存/CPU、稳定性——决定"上不上得了真机"。

> 💡 金句：**成功率决定能不能发布，行为指标决定用户愿不愿意用，资源指标决定能不能量产。**

## 三、分步实操：搭可信评测体系

### 第 1 步：定义评测协议五要素

| 要素 | 要求 |
| --- | --- |
| 场景集 | 与训练场景**按场景切分**（第 5 章教训），含变体外"新组合" |
| Episode 数 | 有统计意义（成功率类 ≥50–100 次起步，按差异灵敏度上调） |
| 随机种子 | 多种子（≥5）且固定记录 |
| 初始状态分布 | 与真机任务分布一致（摆位/光照/干扰采样） |
| 判定规则 | 成功/失败可判定、超时规则、重试规则写死 |

### 第 2 步：搭"回归基准集"（regression suite）

- 从历史任务中选**稳定、覆盖各技能**的 20–50 个场景，作为每次实验必跑的回归集；
- 每次改代码/场景/超参，回归集结果变化即告警；
- **基准集要防"训练污染"**：定期用"冻结的旧版本评测集"交叉验证，防止偷偷过拟合评测分布。

### 第 3 步：建立"仿真-真机对齐样本"（桥接评测）

1. 选 3–5 个"真机可跑"的代表任务作为**锚点**；
2. 每轮新策略先跑仿真全量，再抽锚点任务上真机小样本（10–30 次）；
3. 记录"仿真分 vs 真机分"散点，积累数据后可拟合校准曲线；
4. **目标不是仿真分高，而是散点单调相关**——相关性强时，仿真才能当"筛选器"用。

### 第 4 步：发布门禁（仿真层版本化）

| 门禁 | 条件 | 动作 |
| --- | --- | --- |
| 冒烟门禁 | 新场景能跑通、无报错 | 进基准集 |
| 回归门禁 | 既有任务不掉点（容差内） | 合入 |
| 真机锚点门禁 | 锚点任务达到最低真机分 | 允许真机扩大测试 |
| 发布门禁 | 全量报告+失败模式分析 | 版本发布 |

### 第 5 步：迭代落地流程（防原地打转）

1. **跑评测 → 失败模式聚类**（第 12 章方法搬到仿真）；
2. **归因三问**：场景没覆盖？奖励/任务设计漏洞？策略能力不足？
3. 每轮只改一个变量（加场景/改奖励/调超参/换架构），跑同一评测协议；
4. 记录"实验-结果"表：变量、仿真分、锚点真机分、结论；
5. 连续 N 轮无进展时停止加码，回头审查评测与任务设计——**别用更多实验掩盖评测失效**。

## 五、高频踩坑清单

| 现象 | 根因 | 排查 | 解决 |
| --- | --- | --- | --- |
| 仿真 95% 真机 30% | 评测场景与真机分布脱节 | 锚点对比 | 协议加真机分布采样 |
| 分数越刷越高、真机不涨 | 过拟合评测集 | 冻结旧评测集 | 定期更换/加新变体 |
| "这次好"复现不了 | 种子没固定 | 查记录 | 固定种子+多 seed |
| 失败模式一团乱麻 | 没聚类 | 看失败统计 | 失败聚类+归因三问 |
| 改一个东西全乱了 | 无回归基准 | 查变更 | 每次跑回归集 |
| 迭代 20 轮无进展 | 在错误方向上努力 | 无进展判定 | 停手审查评测/任务设计 |
| 评测协议各人各写 | 无统一文档 | 看协议 | 五要素模板化 |
| 只看成功率不看行为 | 用户抱怨"吓人" | 行为指标 | 加安全/平滑指标 |

## 六、进阶优化

1. **评测场景自动扩充**：把真机失败场景自动"翻译"成仿真变体加进基准集（第 28 章飞轮的评测侧），让评测集跟着真实世界长。
2. **仿真分-真机分校准模型**：积累足够锚点数据后，用简单回归给仿真分"换算"成预测真机分，作为筛选阈值依据。
3. **分层测试金字塔**：单元（单技能）→ 集成（多技能组合）→ 系统（完整任务流），像软件测试一样管理机器人策略版本。
4. **评测即文档**：每版策略发布自带"评测报告"（协议+分数+失败模式+锚点），产品与算法用同一份数据说话。

## 七、本章 TOP3 核心总结

1. **可信评测 = 五要素协议**：场景切分、样本量、多种子、初始分布、判定规则缺一不可。
2. **三层指标 + 回归基准**：成功率定生死、行为定体验、资源定量产；回归集防止改一处毁一片。
3. **仿真分的目标是"能预测真机"**：用真机锚点任务校准，分数相关性比分数高低更重要；无进展 3–5 轮就回头审评测。

> 📌 记住这一句：**没有可信评测的迭代，是在给运气打工；有了可信评测，每一次失败才变成一次投资。**
