## 📌 开篇钩子

同一个抓取任务，有的团队一晚上跑完 5000 万步，有的团队三天才跑 500 万步，而且还不收敛。差距往往不在"算法多高级"，而在**训练系统工程**：环境并行度、RL 超参、奖励设计、日志与早期失败检测。

仿真训练是"用算力换经验"的工厂：工厂效率取决于**单条产线（环境）的仿真步速、产线数量（并行度）、产品设计（奖励/任务）与质检（监控）**。本章把这四件事讲透，给出一套从"能跑"到"跑得快、调得准"的训练工程方法。

## 二、大白话原理：训练速度 = 工厂产能

每秒训练步数 ≈ **单环境仿真步速 × 并行环境数 ×（1 - 空转率）**。

- **单环境步速**：物理步长、渲染、传感器仿真有多快（第 25 章引擎差异）；
- **并行环境数**：同一 GPU 上能同时跑多少个环境（vectorized envs）；
- **空转率**：等待数据、等待更新、I/O 阻塞的时间占比。

加速就三件事：**让每一步更快、让并行更多、让等待更少**。而"调参玄学"的根源，是没用**结构化实验与监控**去分离"算法问题 vs 环境问题 vs 超参问题"。

> 💡 金句：**先让训练"快得能试错"，再谈调出好策略——慢训练会让一切调优都变成赌博。**

## 四、分步实操：训练系统调优路径

### 第 1 步：先让"训练能跑且可复现"

1. 固定随机种子（环境/策略/采样），跑 1 万步冒烟；
2. 确认能稳定产出学习曲线（奖励在涨/任务成功率在涨）；
3. 记录：版本（代码/环境/超参）、日志、曲线存档——**不可复现的训练无法调优**。

### 第 2 步：并行度与吞吐优化（先提速再调参）

| 手段 | 检查点 |
| --- | --- |
| GPU 向量化环境 | 确认 env 数跑满 GPU（不是 CPU 单线程） |
| 物理步长/控制步长 | 满足精度前提下尽量大步长（接触任务谨慎） |
| 渲染频率 | 训练不需要每物理步都渲染时降低渲染频率 |
| 更新频率/batch | 采样-更新配比（如 n_steps 与环境数匹配） |
| 混合精度/编译 | 按框架开启（精度回退监控） |
| 分布式 | 多卡时检查负载均衡与通信开销 |

**验证**：记录 steps/sec，优化前后对比；目标通常是数量级提升空间，先做这些再谈超参。

### 第 3 步：奖励设计（比超参更影响成败）

- **先稀疏后 shaping 的纪律**：先跑通稀疏奖励（成功+1），确认任务可学；再加 shaped reward 提速；
- shaped reward 三条戒律：不鼓励"钻漏洞"（要找 exploit）、不喧宾夺主（稀疏信号仍主导）、可解释（每项 reward 都有日志）；
- 成功判定与真机一致（第 2 章任务书），防止"仿真成功≠任务成功"。

### 第 4 步：PPO 类核心超参调法

| 超参 | 起点与方向 | 症状对应 |
| --- | --- | --- |
| 学习率 | 官方基线起；不收敛降，太慢升 | 发散/停滞 |
| clip 范围 | 0.2 起步 | 更新不稳调小 |
| GAE lambda | 0.95 附近 | 奖励延迟大调高 |
| entropy 系数 | 探索不足加大，不稳减小 | 卡局部最优/熵崩 |
| batch/minibatch | 按显存与并行度 | 更新噪声大调大 batch |
| 环境数 | 越大越稳（受算力限制） | 方差大加环境 |

**纪律**：一次只动一个超参 + 固定预算对比（同 steps 数），用成功率与学习曲线判断，别凭"感觉这次好"。

### 第 5 步：监控与早期失败检测

| 信号 | 含义 | 动作 |
| --- | --- | --- |
| reward 长期平线 | 任务不可学/奖励坏 | 检查奖励与 reset |
| entropy 崩到 0 | 策略过早确定 | 调 entropy/检查观测 |
| 成功率偶发跳变 | 环境 reset/评测 bug | 查 eval 协议 |
| 显存/吞吐突降 | 泄漏/负载不均 | 剖析 |
| 训练曲线"好看"但真机差 | 仿真漏洞/奖励 exploit | 规则化检查+真机锚点 |

**建议**：训练开始 15 分钟内必须能判断"方向对不对"（用小规模快速验证），别让三天实验死在第一天就该发现的 bug 上。

## 五、核心参数详解

| 参数 | 建议起点 | 作用 | 备注 |
| --- | --- | --- | --- |
| 并行环境数 | GPU 满载为准（几十~上千视引擎） | 吞吐/方差 | 从 16/32 起测 |
| 物理步长 | 引擎默认起（接触任务 1ms 量级） | 物理保真 | 与速度权衡 |
| n_steps/batch | 与并行度匹配 | 更新稳定 | 见框架文档 |
| 学习率 | 3e-4 量级起（RL 常用） | 收敛 | 以框架基线为准 |
| 每任务训练预算 | 先设"小预算冒烟"再全量 | 迭代效率 | 防坏实验烧钱 |
| eval 频率 | 每 X 万步一次 | 决策 | 与训练并行不阻塞 |

## 六、高频踩坑清单

| 现象 | 根因 | 排查 | 解决 |
| --- | --- | --- | --- |
| GPU 利用率 10% | 环境没向量化/瓶颈在 CPU | 剖析 | 向量化/异步/降渲染频率 |
| 训练"看似在涨"实则 exploit | shaped reward 有漏洞 | 规则检查 | 稀疏主导+反 exploit |
| 三天不收敛才发现奖励错 | 无早期验证 | 小预算冒烟 | 15 分钟方向验证 |
| 超参一次全改 | 无实验纪律 | 看变更记录 | 单变量+固定预算 |
| 每次结果波动大 | 种子/eval 不固定 | 检查随机性 | 固定种子+多 seed 平均 |
| 物理步长太大接触飘 | 精度-速度没权衡 | 接触测试 | 接触段小步长 |
| 多卡速度不升反降 | 通信开销大 | 看吞吐 | 减少同步频率/单卡向量化优先 |
| 奖励曲线平但真机其实可行 | 奖励尺度/初始化问题 | 看成功率曲线 | 用成功率做主要决策指标 |

## 七、进阶优化

1. **课程学习**：从简单变体（固定位置）开始，成功率达标后逐步加难度（随机位置/干扰），收敛速度和最终性能双赢（与第 27 章课程式域随机化呼应）。
2. **自动超参搜索**：用 Optuna 类工具做小预算搜索（先 10–20 组窄范围），比手调系统；**每次搜索前先保证单次训练可复现**。
3. **异步流水线**：采样与训练异步、eval 独立跑，把空转率压到最低——规模化训练的标准做法。
4. **训练-仿真-真机三角回归**：仿真涨点必须伴随"真机锚点任务"不退化，防止策略在仿真里"刷分"（第 30 章展开）。

## 八、本章 TOP3 核心总结

1. **先算产能再调算法**：steps/sec = 单环境步速 × 并行数 ×（1-空转率），并行与渲染/步长优化通常带来量级提升。
2. **奖励设计先于超参**：稀疏打底、shaping 可解释、成功判定与真机一致；超参单变量+固定预算调。
3. **15 分钟早期验证 + 全程监控**：小预算冒烟、成功率曲线决策、种子固定可复现——坏实验要死在第一天。

> 📌 记住这一句：**训练调优的第一目标不是"找到最优超参"，而是"让每次实验都快到可以犯错、准到可以归因"。**
