## 📌 开篇钩子

第 25 章选好了仿真器，很多团队的第一反应是：拖个平面、放个立方体、导入机器人，开练！

然后 Sim2Real 时才发现：真机的桌面有纹理反光、目标物有 20 种尺寸、光照会随窗户变化、托盘边缘会影响抓取余量——而仿真里全是"纯色平面+标准立方体+恒亮灯光"。**模型在仿真里练会的，是"豆腐块世界"的规则**，到了真机自然水土不服。

## 二、大白话原理：仿真场景是"给模型出题"

### 2.1 场景 = 训练分布的物理载体

回想第 5 章的教训：模型学的是数据分布。仿真场景的本质，是**可控地制造训练分布**——同一个任务，你要能批量生成"桌面纹理、物体颜色、光照、摆放位置、干扰物"的变化，让模型在虚拟世界里见过足够多的"题"。

场景搭建的验收标准不是"好看"，而是：**能不能快速生成覆盖任务关键变量的变体？**

### 2.2 数字孪生不是"越像越好"

数字孪生（把真实工位/房间复刻进仿真）的精度要按用途分层：

| 精度层 | 包含什么 | 用途 | 何时够用 |
| --- | --- | --- | --- |
| 功能层 | 尺寸布局、物体、可达性 | 流程验证、路径规划 | 任务几何验证时 |
| 物理层 | 摩擦、质量、接触、动力学 | 技能训练、Sim2Real | 任务关键物理一致时 |
| 视觉层 | 材质、光照、相机参数 | 感知迁移、数据生成 | 视觉迁移评测达标时 |
| 全真层 | 全部细节+动态环境 | 高保真演示 | 极少需要，成本极高 |

> 💡 金句：**数字孪生的目标是"该像的地方像"——把预算花在任务关键的物理与视觉要素上。**

## 三、分步实操：从空场景到可训练场景

### 第 1 步：先列"场景变量矩阵"（从第 7 章拿来）

把业务场景翻译成变量：桌面纹理（3 种）、目标物（5 种×尺寸/颜色）、光照（3 档）、遮挡物（有/无）、位置网格（9 格）……**这个矩阵就是场景搭建的施工图**，也决定了哪些资产必须建。

### 第 2 步：资产准备与检查（机器人 + 物体 + 环境）

| 资产 | 检查点 |
| --- | --- |
| 机器人 URDF | 关节方向/限位正确、碰撞体简化合理、惯量/质量合理、默认姿态正确 |
| 末端工具 | TCP 与真机一致、夹爪开合模型正确 |
| 操作物体 | 尺寸/质量/摩擦可调、有碰撞网格+视觉网格（可分开） |
| 环境 | 桌面/货架/托盘等，尺寸按真实布局 |
| 材质与光照 | 任务关键表面（反光/纹理）有区分度 |

**质量门禁**：每个资产导入后跑"最小物理测试"（掉落、碰撞、抓取），不合格不入库（延续第 9 章的质量门禁思想）。

### 第 3 步：搭建"基场景"（先 80% 时间做 20% 关键任务）

1. 用真实工位尺寸搭基场景（卷尺量出来的尺寸比"看着像"重要）；
2. 摆放第一版任务物体（覆盖变量矩阵的核心组合）；
3. 跑通端到端：感知输入 → 策略/规划 → 执行 → 成功判定；
4. **先证明"场景能练任务"，再谈丰富度**——很多团队死在"场景华丽但任务跑不通"。

### 第 4 步：变体生成机制（场景的"批量出题"能力）

- 参数化摆放：物体位置/姿态/数量用脚本生成；
- 材质/光照随机化：按区间采样；
- 干扰物/背景随机化；
- 每个变体记录"生成参数"，输出给训练与数据卡（呼应第 7/9 章）——**可复现的随机，才是好的随机**。

### 第 5 步：数字孪生分级落地（用于真实场地复刻时）

1. 现场测量与拍照 → 先做功能层（布局、可达区）；
2. 真机标定数据（第 2 章）导入：桌面高度、相机外参、机器人基座位姿；
3. 关键物理对齐：物体质量/摩擦用真机实验标定（第 28 章系统辨识）；
4. 视觉对齐：相机参数（FOV/分辨率/噪声）、关键材质与光照；
5. **验收 = 迁移评测**：同一策略仿真与真机的表现差进入可接受范围，而不是"人眼看着像"。

## 四、核心参数详解

| 参数/项 | 建议起点 | 作用 | 备注 |
| --- | --- | --- | --- |
| 场景布局误差 | ≤2–5cm（功能层） | 可达性 | 尺寸用实测 |
| 摩擦系数 | 真机实测或文献同类 | 抓取/推 | 分物体分别设 |
| 质量 | 真机/规格书 | 动力学 | 别默认 1kg |
| 相机 FOV/分辨率 | 与真机一致 | 视觉迁移 | 含畸变模型 |
| 变体数量 | 每任务 ≥30–100（视难度） | 覆盖度 | 见第 5 章均衡 |
| 材质区分度 | 任务可辨识 | 感知训练 | 别全用纯色 |

## 五、高频踩坑清单

| 现象 | 根因 | 排查 | 解决 |
| --- | --- | --- | --- |
| 场景华丽但任务跑不通 | 先做了美术没做功能 | 端到端冒烟 | 先功能后美术 |
| 真机布局和仿真差很多 | 尺寸靠"看着像" | 实测对比 | 卷尺+标定数据 |
| 物体质量默认 1kg | 没查规格 | 看动力学行为 | 按规格书/实测设置 |
| 抓取仿真成功真机失败 | 摩擦/接触参数不符 | 真机抓取对照 | 摩擦标定+域随机化 |
| 每次随机结果不可复现 | 无种子/无记录 | 看生成日志 | 记录种子与参数 |
| 数字孪生越做越像越没用 | 精度加在无关细节 | 对照用途分层 | 按任务关键要素投入 |
| 资产各改各的版本乱 | 无资产中心 | 查资产版本 | 版本化+CI 式冒烟 |
| 场景变量没覆盖长尾 | 只搭了"标准题" | 对照变量矩阵 | 按矩阵补变体 |

## 六、进阶优化

1. **程序化场景生成**：把"变量矩阵"写成程序化生成器（布局/物体/光照随机采样），配合 GPU 并行渲染，一夜生成上万变体——虚拟数据工厂的雏形（第 27 章）。
2. **真实感材质库**：为业务物体建"真实材质包"（织物/塑料/金属/玻璃的参数化材质），视觉迁移收益远大于几何细节。
3. **"任务关键度"评审**：每个场景元素标注"影响任务的关键度"，评审时先保关键元素，防止把预算花在窗外的树。
4. **场景版本与数据版本联动**：场景生成参数进数据卡（第 7/9 章），仿真数据出问题时能反查到"哪版场景产的"。

---

## 七、本章 TOP3 核心总结

1. **场景 = 可控的训练分布**：先列变量矩阵，再搭基场景，最后做变体生成机制；先"能练任务"后"丰富好看"。
2. **数字孪生按功能/物理/视觉分层**：该像的地方像，用"迁移评测"验收，而不是人眼像。
3. **资产要有质量门禁和版本**：机器人/物体/场景入库前跑最小物理测试，生成参数全程记录。

> 📌 记住这一句：**仿真场景不是美术作品，是给模型出的考卷——考点覆盖全，才算好场景。**
