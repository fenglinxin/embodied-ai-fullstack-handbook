## 📌 开篇钩子

产线机器人的经典现场：上午跑得好好的，下午开始"抽风"——动作卡一下、末端慢慢漂、偶尔直接罢工。工程师到场三板斧：重启、重刷、换备件，好了两天又犯。**因为没人知道根因，每次"修好"都是碰运气。**

真机故障最贵的成本不是修，而是**定位**。而定位的前提不是聪明，是"痕迹"：日志、时间戳、回放数据、状态记录。没有痕迹的现场，神仙也难断案；痕迹齐全的故障，大多是"现象→分层→复现→根因→修复→回归"的标准流程。

本章给一套真机排查方法论：故障怎么分类、日志与回放怎么用、卡顿/漂移/失效三大类怎么查、以及怎么把每次排查沉淀成团队案例库。

## 二、大白话原理：故障排查的"分层定位法"

### 2.1 现象四问（先花 5 分钟问清楚）

1. **什么现象**：卡顿/漂移/失效/异响/报警？（描述要可测量）
2. **什么时候开始**：一直有/升级后/特定时段/特定动作？
3. **什么条件下发生**：满载/高温/特定场景/特定指令？
4. **复现吗**：稳定复现/偶发/概率多少？

**四问的价值**：把"机器人坏了"变成"机器人在 XX 条件下做 XX 动作时出现 XX 现象"，排障范围立刻缩小 80%。

### 2.2 分层排查（从外到内）

| 层 | 查什么 | 手段 |
| --- | --- | --- |
| 环境层 | 温度/供电/网络/光照变化 | 环境日志 |
| 系统层 | CPU/内存/线程/进程 | 系统监控 |
| 通信层 | 丢包/延迟/断连 | 通信日志 |
| 算法层 | 感知/规划/控制输出 | 模块日志+回放 |
| 硬件层 | 电机/编码/线缆/松动 | 硬件自检+测量 |

**原则**：从便宜好查的层开始（先环境/系统，再算法/硬件），每层排除都要有证据，禁止"跳层瞎猜"。

> 💡 金句：**故障不可怕，可怕的是没有痕迹的故障——日志与回放，是现场工程师的显微镜。**

## 三、分步实操：三大类故障排查流程

### A 类：卡顿/动作不连贯

| 步骤 | 动作 |
| --- | --- |
| 1 分类 | 周期性卡顿/偶发长卡/动作内断点 |
| 2 查系统 | CPU 尖峰？GC？线程饿死？温度降频？ |
| 3 查通信 | 指令流断裂？DDS 丢包？控制超时？ |
| 4 查算法 | 规划耗时突增？感知漏帧导致等待？ |
| 5 查硬件 | 驱动器报警？编码器毛刺？ |
| 修复示例 | 偶发长卡多为系统层（调度/GC/降频）；周期卡顿查控制与通信周期；动作内断点查规划-控制衔接 |

### B 类：漂移/精度退化

| 步骤 | 动作 |
| --- | --- |
| 1 分类 | 瞬时漂/渐进漂/换向漂/随负载漂 |
| 2 查标定 | 外参/TCP/零位版本与最近变更（第 2/34 章） |
| 3 查机械 | 松动/磨损/背隙增大/热变形 |
| 4 查控制 | 前馈/负载参数（第 21 章） |
| 5 查里程计 | 打滑/丢脉冲（移动平台，第 33 章） |
| 修复示例 | 渐进漂优先查热与磨损；换工具后漂查 TCP；随负载漂查辨识 |

### C 类：失效/罢工/安全停机

| 步骤 | 动作 |
| --- | --- |
| 1 看报警码 | 安全链/驱动器/系统哪层触发 |
| 2 查触发链 | 是真实保护还是误触发（传感器坏/阈值过紧） |
| 3 查恢复 | 恢复路径是否可达（第 41 章 L0–L3） |
| 4 查批量 | 单台还是批次问题（第 36 章可靠性） |
| 修复示例 | 误触发优先查传感器与阈值；批次问题查部件/工艺 |

## 四、日志与回放体系（排查的基础设施）

| 工具 | 用途 | 要点 |
| --- | --- | --- |
| 系统日志 | CPU/内存/温度/进程 | 高分辨率采样，出事能回溯 |
| 模块日志 | 各模块状态/异常 | 统一格式+时间戳+链路 ID |
| rosbag/数据录制 | 全量回放 | 带硬件时间戳（第 41 章） |
| 故障快照 | 触发时自动保存 | 日志+状态+最近 N 秒数据 |
| 看门狗 | 发现"假死" | 分级恢复 |

**建议**：每台机器默认开"环形录制"（保留最近 10–30 分钟全量数据），故障发生后一键冻结——**否则故障过去了，证据也过去了**。

## 五、核心参数详解

| 项 | 建议 | 作用 |
| --- | --- | --- |
| 日志保留 | 环形 10–30 分钟全量+关键日志长期 | 事后复现 |
| 采样频率 | 系统监控 1Hz+，控制链路按需高频 | 定位抖动 |
| 故障快照 | 触发前后各 N 秒 | 上下文 |
| 复现实验 | 固定条件重复 ≥10 次 | 概率确认 |
| 案例库字段 | 现象/条件/根因/修复/预防 | 沉淀 |

## 六、高频踩坑清单（排查本身的坑）

| 现象 | 根因 | 解决 |
| --- | --- | --- |
| 修好两天又犯 | 只治标没找根因 | 根因分析+预防措施 |
| 复现不了 | 条件没记录全 | 现象四问+环境日志 |
| 换了一堆件才好 | 无证据的盲换 | 分层排查每步留证 |
| 日志太多找不到 | 无统一格式/链路 ID | 统一日志+链路追踪 |
| 偶发故障被当个案 | 无批次统计 | 故障登记+趋势分析 |
| 现场改完不回填配置 | 版本失控 | 配置版本化（第 11/36 章） |
| 排查只到"重启就好" | 无根因 | 看门狗+快照抓现行 |
| 案例不沉淀 | 无案例库 | 复盘入库+新人培训 |

## 七、进阶优化

1. **故障自诊断上移**：把常见根因写成在线诊断规则（如"漂移+温度高→提示热变形排查"），机器自己先给方向。
2. **预测性维护**：监控电机电流/温度/编码异常的长期趋势（第 21/36 章），在故障发生前预警。
3. **远程排障能力**：现场数据+日志自动上云，专家远程回放分析——减少"等专家到场"的停机时间。
4. **根因率 KPI**：把"带根因的故障占比"作为团队指标，逼着团队从"修好就行"走向"根因闭环"。

---

## 八、本章 TOP3 核心总结

1. **现象四问+分层排查**：从环境→系统→通信→算法→硬件逐层排除，每步留证据，禁止跳层瞎猜。
2. **痕迹是排查的基础设施**：环形录制+统一日志+故障快照，让偶发故障"跑不掉"。
3. **根因闭环>治标**：修复必须带预防措施，案例库沉淀+根因率 KPI，让团队越老越值钱。

> 📌 记住这一句：**现场工程师最贵的不是扳手，是"定位问题"的方法论——而它建立在日志与复现之上。**
