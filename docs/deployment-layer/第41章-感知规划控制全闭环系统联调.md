## 📌 开篇钩子

感知 99 分、规划 95 分、控制 98 分——三个模块单独测都优秀，装到一起却事故频发：感知刚更新了目标位置，规划还在用旧轨迹；控制收到的新目标与当前轨迹不连续，"咔"地急停；人一靠近，三个模块各按各的逻辑反应，机器人像个精神分裂患者。

**系统联调的本质，是把"各自优秀的模块"变成"一个自洽的系统"**：数据流要闭环、状态要一致、异常要有统一处理、模块间的"接口假设"要逐个对齐。本章讲全闭环联调的方法论：闭环架构、状态机与异常体系、回放联调、以及逐级放开的验收路径。

## 二、大白话原理：闭环系统的三个"一致"

### 2.1 数据要"闭环"

感知输出目标 → 规划生成轨迹 → 控制执行 → 本体状态回感知/规划，形成闭环。联调首先检查的，就是这个环的每个"接缝"：
- 时间一致（第 3/40 章）；
- 坐标系一致（感知的目标在谁的坐标系）；
- 语义一致（"目标丢失"在各模块是不是同一个意思）。

### 2.2 状态要"一致"

机器人需要一个**系统级状态机**（空闲→任务中→暂停→异常→恢复），所有模块围绕它行动。最怕的是"感知觉得自己在任务中、规划已经放弃、控制还在执行旧轨迹"——**各模块状态不一致，是灵异事故的头号来源**。

> 💡 金句：**联调不是把模块接起来，是把它们的"世界观"对齐——时间、坐标、状态，一个都不能各说各话。**

## 三、分步实操：全闭环联调六步

### 第 1 步：接口契约审计（先纸面后代码）

对每个模块间接口过一遍：
- 消息定义：字段、单位、坐标系、频率、超时语义；
- 异常语义：目标丢失/规划失败/控制超差如何表达；
- 版本：接口变更走评审（模块独立开发时最容易"悄悄改坏对方假设"）。

产出**接口契约表**：谁生产、谁消费、频率、延迟预算、异常码。这张表是联调的宪法。

### 第 2 步：系统状态机与异常分级

| 级别 | 例子 | 处理 |
| --- | --- | --- |
| L0 正常 | 任务执行 | 日志 |
| L1 可容忍 | 单帧漏检 | 重试/下一帧 |
| L2 需降级 | 目标持续丢失/规划超时 | 减速、保守模式、重规划 |
| L3 需停止 | 控制超差/安全事件 | 安全停车+人工确认 |

所有模块的异常都归一到这套分级，由**系统仲裁器**（状态机）统一决策——禁止各模块自己乱停车/乱重试。

### 第 3 步：回放联调（真机前的主战场）

1. 用真机/仿真录一段**带时间戳的全量数据流**（感知输入+状态+指令+结果）；
2. 让新模块消费回放数据，对比输出与录制时的期望；
3. 制造"坏数据"（丢帧/跳变/超时）回放，验证异常处理；
4. **收益**：80% 的接口与逻辑 bug 在真机前暴露，且可复现、可回归。

### 第 4 步：开环→闭环逐级放开的真机联调

| 阶段 | 做什么 | 通过标准 |
| --- | --- | --- |
| 开环注入 | 用固定脚本输入驱动各模块 | 各模块响应正确 |
| 半闭环 | 感知真跑，规划/控制用安全包线 | 数据流正确 |
| 低速闭环 | 全链路真跑，限速 20–30% | 行为合理、无异常抖动 |
| 全速闭环 | 目标速度跑 | 任务成功率与安全达标 |
| 长跑 | 连续运行 | 无状态漂移/内存泄漏 |

### 第 5 步：异常演练（专门制造故障）

- 拔相机/断通信/目标丢失/规划超时/控制超差，逐一验证系统按 L1–L3 处理；
- 验证"恢复路径"：异常处理后能回到安全状态，而不是卡死在半路；
- 演练结果进联调报告，未覆盖的异常场景列入待办。

### 第 6 步：联调验收与回归

- 任务级：成功率、节拍、故障率（第 30 章协议搬到整机）；
- 系统级：状态机无非法迁移、异常恢复率 100%、长跑无漂移；
- 建立**回归场景集**：每次改版跑"回放集+关键真机场景"，防止修 A 坏 B。

## 五、高频踩坑清单

| 现象 | 根因 | 排查 | 解决 |
| --- | --- | --- | --- |
| 各模块状态不一致乱动 | 无系统状态机 | 看状态日志 | 仲裁器统一状态 |
| 目标位置"瞬移" | 坐标系不一致 | 重投影检查 | 统一坐标系 |
| 规划轨迹与控制不连续 | 无轨迹平滑/切换协议 | 看指令流 | 平滑衔接/模式切换 |
| 目标一丢就乱来 | 异常处理各自为政 | 看各模块异常逻辑 | 统一分级+仲裁 |
| 真机联调反复炸 | 跳过回放直接上真机 | 回顾流程 | 回放联调先行 |
| 恢复路径卡死 | 只设计了异常没设计恢复 | 演练 | 恢复路径专项设计 |
| 修好 A 又弄坏 B | 无回归 | 看变更 | 回归场景集 |
| 接口悄悄变没人知道 | 无契约评审 | 查接口版本 | 契约表+评审 |

## 六、进阶优化

1. **状态机可视化与审计**：系统状态迁移全部记录（谁触发、何时、为何），出事后能精确回放"系统当时在想什么"。
2. **影子模式联调**：新模块影子运行对比旧模块（第 37 章），行为一致再切换，联调升级零风险。
3. **仿真/真机双轨联调**：先仿真全闭环（第 25–31 章），再真机跑同一套场景——问题分层：仿真抓逻辑、真机抓物理。
4. **"系统体检"自动化**：启动自检（节点/接口/标定/时间同步）+ 周期体检脚本，联调问题从"现场发现"变"开机拦截"。

## 七、本章 TOP3 核心总结

1. **三个一致是闭环前提**：时间、坐标系、状态语义在接口契约表里对齐，系统状态机统一仲裁。
2. **回放联调 > 现场试错**：带时间戳数据流+坏数据注入，80% 问题在真机前暴露并可回归。
3. **异常分级+恢复路径+演练**：L0–L3 统一处理、恢复路径专项设计、故障演练进验收。

> 📌 记住这一句：**联调联的不是接口，是各模块对"同一个世界"的理解。**
