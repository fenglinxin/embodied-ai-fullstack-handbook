## 📌 开篇钩子

单模块优化做完（第 38–39 章），整机一跑还是"慢半拍"：图像 30ms 推理 25ms 看着都不慢，加起来却 200ms——因为**每个模块都在排队等上一级**，中间还夹着拷贝、调度、同步等待。机器人系统的延迟是"链路问题"，不是"单点问题"。

更隐蔽的是抖动：平均 80ms 的链路，偶尔飙到 300ms——机器人平时看着还行，一遇到突发（人靠近、物体移动）就抽风。**对机器人来说，延迟的可预测性（P99/P99.9）比平均值重要得多**。

本章把"从摄像头到电机"的整条链管起来：延迟预算怎么建、流水线怎么并行、每段怎么压、以及怎么验收"手眼协调"的真实手感。

## 二、大白话原理：链路延迟的三笔账

### 2.1 延迟 = 处理时间 + 排队时间 + 同步等待

- **处理时间**：每段真实干活的时间（第 38 章已优化）；
- **排队时间**：数据在上游等着被处理（流水线没打通）；
- **同步等待**：为了"拿到最新数据"而等待慢模块（同步点设计问题）。

三段里，后两段往往贡献了"看不见的 100ms"——模块单独测都很快，串起来却慢。

### 2.2 频率分层：别让慢模块拖住快模块

感知 15Hz、规划 10Hz、控制 500Hz——如果控制每周期都等规划，系统就被拖到 10Hz。正确做法是**各层按自己的频率跑，中间用"最新有效数据"衔接**：控制永远用最新的目标（哪怕规划只更新了 10 次/秒），快层不等慢层。

> 💡 金句：**低延时系统的秘密不是"每段都快"，而是"快段不等慢段、慢段结果常新"。**

## 三、分步实操：全链路调优六步

### 第 1 步：画链路图 + 建延迟预算表

从"物理事件发生"到"执行器响应"逐段画：
> 传感器曝光 → 采集 → 感知（检测/位姿）→ 融合 → 预测/规划 → 推理/决策 → 通信 → 控制 → 执行器

给每段设预算（示例，按任务改）：曝光 5ms + 采集传输 5ms + 感知 20ms + 规划 20ms + 决策 15ms + 通信 5ms + 控制 1ms = **端到端预算 71ms**（≈14Hz 决策带宽）。**预算表是调优的靶子：哪段超了改哪段，别整条瞎压**。

### 第 2 步：埋点测量（没有数据不调优）

- 每段打时间戳（硬件时间戳优先，第 3/35 章）；
- 端到端与分段都统计 P50/P95/P99/max；
- 记录"数据年龄"（age of data）：执行时用的观测是多久前的——**这才是机器人真正感受到的延迟**。

### 第 3 步：流水线并行（压排队时间）

- 采集 / 感知 / 决策 / 控制各跑独立线程/进程，队列解耦；
- 双缓冲/环形缓冲避免锁竞争；控制线程绝不阻塞等 AI（第 37 章）；
- 目标：稳态下每段几乎连续工作，队尾延迟 = 最大单段耗时而不是各段之和。

### 第 4 步：按"信息新鲜度"取舍（压同步等待）

| 场景 | 做法 |
| --- | --- |
| 动态目标 | 感知高频+决策用最新帧（宁用新帧粗结果） |
| 静止任务 | 可等待精感知（慢但准） |
| 高频控制 | 用动作块/轨迹插值（一次决策管 N 步，第 22 章） |
| 多传感器 | 以"最晚必需数据"为同步点，别等所有慢传感器 |

### 第 5 步：压单段剩余大头（按瀑布图）

- 若感知是大头：轻量模型级联（快模型先粗判，慢模型精算少数目标）；
- 若推理是大头：动作块/缓存/批 1 优化/量化（第 38–39 章）；
- 若通信是大头：共享内存/减小消息/零拷贝；
- 若控制受限：看第 21 章控制延迟预算。

### 第 6 步：验收（手感测试）

- **阶跃响应**：物体突然移动/命令突变，测"事件→动作开始"延迟分布；
- **跟踪测试**：机器人跟踪移动目标，测跟踪误差（比单段延迟更真实）；
- 满载+长跑：P95/P99 不漂；
- 目标：**延迟预算达成 + P99 稳定**，才敢宣称"手眼协调"。

## 五、高频踩坑清单

| 现象 | 根因 | 排查 | 解决 |
| --- | --- | --- | --- |
| 各段快、整机慢 | 排队/同步等待 | 数据年龄分析 | 流水线并行+异步解耦 |
| 机器人"想一下动一下" | 决策频率太低且无动作块 | 看指令流 | 动作块+插值 |
| 平时顺、突发抽风 | 抖动集中在某段 | P99 定位 | 预热/锁内存/降级路径 |
| 控制等 AI 导致抖动 | 同步设计错误 | 线程等待分析 | 控制绝不阻塞（第 37 章） |
| 用的总是 200ms 前的图 | 感知队列积压 | 数据年龄 | 队列背压/丢旧帧 |
| 每加一个模块慢一截 | 无预算表 | 对比预算 | 超预算的模块单独谈 |
| 阶跃响应忽快忽慢 | 首帧/缓存未预热 | 重复阶跃 | 预热+缓存策略 |
| 只优化了平均没管 P99 | 指标错误 | 看分布 | P95/P99 进验收 |

## 六、进阶优化

1. **预测补偿延迟**：用第 16 章预测器把目标状态外推到"执行时刻"，让系统"看起来零延迟"——动态抓取/避让的质变技巧。
2. **关键路径与非关键路径分离**：安全关键路径（碰撞检测→急停）最短化；任务关键路径（感知→动作）次之；日志/遥测走旁路，永不抢主路径。
3. **确定性调度编排**：为每段设定周期与优先级（如 Linux RT + 分区调度），用"错过率"而不是平均延迟做 SLA。
4. **回放驱动的回归**：用录制的真实数据流（含突发场景）做延迟回归，每次改版跑同一套"延迟考卷"。

---

## 七、本章 TOP3 核心总结

1. **预算表先行**：端到端逐段设预算，数据年龄才是机器人真实感受到的延迟。
2. **并行与分层是关键**：快段不等慢段、感知≥决策频率、动作块桥接低频决策，把"延迟之和"变成"队尾≈最大段"。
3. **验收看 P99 与阶跃**：可预测性比平均值重要，阶跃响应与跟踪误差才是"手感"。

> 📌 记住这一句：**机器人不会告诉你"我慢了 100ms"，它只会表现为"跟不上"——而预算表能让你提前抓住它。**
