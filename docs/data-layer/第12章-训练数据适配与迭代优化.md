## 📌 开篇钩子

数据管线全部打通后，团队容易陷入两种极端：一种是"数据是数据、模型是模型"，采集的人不知道模型吃不下什么，训模型的人不知道数据为什么长这样；另一种是训一次模型就要重采一批数据，永远在"数据怎么又不够用"的循环里。

真相是：**数据和模型之间有一层"适配器"**。模型要求 224×224 的输入，你的相机是 1080p；模型输出 10Hz 的动作块，你的数据是 500Hz 的关节命令；模型需要归一化的末端增量，你的数据存的是绝对关节角。适配做不好，再好的数据也喂不进去。

而真正让数据变成资产的是最后一环——**闭环**：评测失败 → 归因（模型/数据/适配）→ 数据迭代 → 回归验证。本章是数据层收官篇，把"训练数据适配 + 数据-模型迭代"讲透。

## 二、大白话原理：数据适配在解决什么？

### 2.1 模型不是"直接吃数据"，而是"吃约定的格式"

一个 VLA/模仿学习模型通常约定：**观测分辨率、帧率（多久一帧）、帧堆叠数（看几帧）、动作表示（增量/绝对/关节/末端）、动作频率与预测步数（action chunk）、数值归一化范围**。

你的数据若与约定不符，会出现三类"慢性病"：
- **信息丢失**：1080p 缩到 224 时丢失细节——正常，但训练/推理必须用同一缩放；
- **表示错位**：模型学的是末端增量，你喂绝对位姿——学得慢或学不会；
- **频率错配**：模型按 10Hz 预测，数据里是 500Hz——每个训练样本的动作目标都不在"该在的时刻"。

### 2.2 适配的目标是"无损翻译"，不是"改数据"

适配应该在数据与模型之间加一层**可复现的转换器**（dataset adapter），而不是手工改原始数据。原始数据保持"最真"，适配层按模型版本翻译——这样换模型时不用重采，换数据时不用重写模型。

> 💡 金句：**原始数据是真相，适配层是翻译——翻译可以换，真相不要动。**

## 三、分步实操：训练前 6 项适配检查

### 第 1 项：观测尺寸与编码

- 统一 resize 到模型输入（如 224/336），**训练与推理用同一套缩放与归一化**；
- 检查颜色空间（RGB/BGR）、归一化均值方差是否与预训练权重一致；
- 深度/点云按模型协议编码（单通道/伪彩色/体素化），写进 adapter 并单测。

### 第 2 项：帧率与帧堆叠

- 决定训练帧率（如 10–15Hz 采样）并**统一重采样规则**（取整帧/最近邻）；
- 配置帧堆叠（如连续 2–6 帧）时，注意跨 Episode 边界禁止堆叠；
- 高频动作通道按主时间轴对齐（衔接第 3 章），避免"半帧错位"。

### 第 3 项：动作空间翻译

| 模型动作空间 | 你的数据 | 适配动作 |
| --- | --- | --- |
| 末端增量 | 末端增量 | 直接（核对缩放与单位） |
| 末端绝对位姿 | 末端增量 | 需轨迹积分（注意误差累积，最好源头统一） |
| 关节角目标 | 关节角命令 | 核对顺序/方向/单位/限位 |
| 关节角增量 | 关节角绝对 | 差分（注意跨帧跳变） |
| 夹爪 | 连续开度/离散开关 | 统一编码，单独通道 |

**核验动作**：转换后随机抽 5–10 条重放，检查平滑性与物理合理性。

### 第 4 项：归一化与数值范围

- 图像按模型要求归一化；
- 动作按数据集统计归一化（mean/std 或 min/max）时，**统计量必须随训练集版本存档**，推理端使用同一统计量；
- 记录动作的物理单位（弧度/度、米/毫米），杜绝"单位事故"。

### 第 5 项：训练/评测切分复核

- 确认切分按**场景/物体**而非文件随机（第 5 章）；
- 训练集 adapter 与评测集 adapter 必须一致；
- 发布前跑"切分泄漏检查"：训练与评测的轨迹相似度分布应无异常重合。

### 第 6 项：适配层冒烟测试

- 固定 3–5 条 Episode，跑 adapter 输出样本，人工/脚本核对张量形状、数值范围、时间对齐；
- 每次改 adapter（代码/参数）跑冒烟 + 黄金评测，防"悄悄改坏"。

## 四、失败归因三问（掉点后先别重采）

模型成功率掉了，先回答三个问题再动数据：

| 问题 | 怎么查 | 结论指向 |
| --- | --- | --- |
| 适配对吗？ | 回放训练样本 vs 原始数据；检查分辨率/动作/频率 | 适配 bug → 修 adapter，不是重采 |
| 数据覆盖对吗？ | 按失败场景查训练分布（任务×物体×位置） | 覆盖缺失 → 补采对应桶 |
| 数据干净吗？ | 质量分报告 + 抽检失败场景样本 | 脏数据 → 清洗/标记修复 |

> 经验比例（非定律）：早期项目里"看似数据问题"的失败，相当一部分其实是适配或评测问题——先花半天做归因，能省一周重采。

## 五、数据-模型协同迭代流程（闭环标准动作）

### 第 1 轮：基线闭环
小数据（第 10 章 MVP）→ 训基线 → 建黄金评测集（变体+变体外）→ 记录失败模式清单。

### 第 2 轮：数据迭代
按失败模式排序（频次×业务代价）→ 补采/增强对应桶（第 5、7、10 章）→ 清洗打分（第 4、9 章）→ 发布新数据集版本。

### 第 3 轮：模型再训与回归
新数据版本 + 同模型配置重训 → 黄金评测 + 原任务回归 → 记录"数据版本×成功率"曲线。

### 第 4 轮：版本协同
实验记录三元组：**数据集版本 + 适配器版本 + 模型代码版本**。任何一次涨/掉点都能归因到三者的变化。

> 迭代节奏建议：小步快跑（每次只改一个变量），比"憋大招换全量"更高效——单变量实验才可归因。

## 六、核心参数详解

| 参数 | 建议起点 | 作用 | 备注 |
| --- | --- | --- | --- |
| 训练采样帧率 | 10–15Hz（视任务） | 控制样本量 | 高频任务另议 |
| 帧堆叠 | 2–6 帧 | 速度/动态信息 | 跨 Episode 禁堆 |
| 动作预测步数（chunk） | 8–64 步（按模型） | 平滑与效率 | 与真机控制频率配合 |
| 归一化统计量 | 随数据集版本存档 | 可复现 | 推理端同源 |
| 冒烟测试样本 | 3–5 条 | 适配正确性 | 每次改动必跑 |
| 黄金评测集 | 每任务 ≥20–50 新组合 | 迭代度量 | 独立于训练 |

## 七、高频踩坑清单

| 现象 | 根因 | 排查 | 解决 |
| --- | --- | --- | --- |
| 训练时好、真机动作乱 | 推理端适配与训练不一致（缩放/归一化/频率） | 对比两端 adapter 输出 | 训练/推理共用同一 adapter |
| 换模型后全崩 | 新模型动作空间/帧协议不同 | 查适配层版本 | 适配器按模型版本化，不硬改数据 |
| 掉点后盲目重采 | 没做失败归因 | 三问排查 | 先查适配/覆盖/质量 |
| 数据越迭代越乱 | 无版本记录 | 查实验三元组 | 数据集/适配/代码版本绑定 |
| 评测涨了真机不涨 | 评测集与训练分布同源 | 查切分泄漏 | 按场景/物体独立评测集 |
| 归一化统计量漂移 | 每版重算未存档 | 查训练日志 | 统计量随版本存档 |
| 重放动作"跳变" | 动作空间翻译出错 | 抽验重放 | 转换后强制重放冒烟 |

## 八、进阶优化

1. **适配器即代码**：把"原始数据→训练样本"写成带单测的库，任何模型/任何数据都走同一入口——适配器质量直接决定数据复用率。
2. **失败模式知识库**：把归因结论沉淀成（现象→根因→解决）条目库，团队掉点后先查库再排查，越用越快。
3. **数据效率预算制**：为每次数据迭代设定"投入-收益"记录（补采 N 条 → 成功率 +X%），三个月后就知道哪类数据最值钱。
4. **通往模型层**：数据层的一切努力，最终要交给模型层兑现——从下一章起，进入感知、预测、规划、控制与 VLA 的工程拆解。

## 九、本章 TOP3 核心总结

1. **适配层是数据与模型的翻译官**：6 项检查（分辨率/帧率/堆叠/动作空间/归一化/切分）训练推理必须一致，adapter 版本化、带冒烟测试。
2. **掉点先归因再动手**：适配 → 覆盖 → 质量三问，多数"数据问题"其实是适配或评测问题。
3. **迭代要版本协同**：数据集版本 + 适配器版本 + 模型代码版本三件套绑定，小步单变量迭代。

> 📌 记住这一句：**数据层没有"做完"的那天——它和模型一起进化，直到业务验收那一刻。**
